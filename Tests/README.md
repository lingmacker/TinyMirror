# 媒体回归检查

```sh
bash scripts/check-media.sh
```

需要完整 Xcode 和项目正常构建所需的工具。脚本在 `.build/native-audio-tests/` 隔离构建固定版本的 native core，不覆盖运行中开发应用可能加载的 `native/build/` 库，再由 macOS 的 `afconvert` 生成三秒双声道纯音。播放检查使用静音 renderer，不录制用户音频，不启动应用窗口。

## 原生接收层

`RAOPAudioBufferChecks.c` 测试实际 UxPlay 重排缓冲，并启用 AddressSanitizer / UndefinedBehaviorSanitizer：

- AAC-ELD 无音频占位包、只有 RTP 头的包，以及静音后的第一包。
- 乱序占位包不覆盖已收到的声音；真正丢包仍请求重传并按顺序恢复。
- 16 位序号回绕、重复包、满窗口及不重传模式。
- 4000 次静音 / 有声切换与短包边界。

未修补的固定上游版本会在“声音 → 无音频占位 → 声音”用例失败，后续声音被误判为等待丢包重传。修复以 `native/patches/uxplay-audio-silence.patch` 保存，由 bootstrap 应用，不依赖手工修改 vendor。

`RAOPAudioClockChecks.c` 调用实际音频启动和 RTP 时间换算：检查 ALAC / AAC-ELD 的一秒采样精度、负偏移和时间戳回绕。未修补版本因整数除法每秒误差约 32.5 微秒；修复保存在 `native/patches/uxplay-audio-clock.patch`。

`RAOPALACPauseChecks.c` 用 Apple 编码器生成的真实 32 字节 ALAC 静音帧，经 AES-CBC 加密、本地 UDP 和生产 RTP 接收循环，验证首尾静音、重传、序号回绕都不丢帧。解密后的原始帧交给 Swift 中的系统解码器，断言输出完整 352 帧双声道零 PCM，而不是把 44 字节 RTP 包当作无音频占位。旧的丢弃／头部占位方案会在此测试中失败。修复保存在 `native/patches/uxplay-alac-pause.patch`。

还单独验证“最后一包重传”和“首次同步”只从控制端口到达、之后没有普通数据包的情况：已齐备的声音必须立即按序放行，不得等下一包数据才能播放。这两项在旧循环分别只收到 1/3、0/2 包；修复保存在 `native/patches/uxplay-audio-control-drain.patch`。

`AudioBridgeFormatChecks.c` 验证真实 C 回调保留 `usingScreen`；`ReceiverFormatChecks.swift` 通过无网络 C stub 验证实际 Swift 回调解析及旧版格式兼容，不启动发现服务。

## Swift 播放层

`MediaPlaybackChecks.swift` 使用生产格式封装、播放器及原生解码器：

- AAC-ELD 480/512、AAC-LC、ALAC 和 PCM 格式、包时长与数据校验。
- 正确解析 ADTS；原生解码后的能量及双声道频谱检查，发现静音、削波、采样率错误或波形断裂。
- 解码器短暂未就绪时，保留开头八包，不直接丢弃。
- 256 包突发全部按原字节顺序送达，超过窗口的输入受限；送达后的 AAC-ELD 仍能解码为干净双声道纯音。旧的 32 包上限在该用例只收到 32/256 包。
- 待播状态下停止，清空缓冲并释放全部入队名额。
- 视频先到、音频延后、静音视频时钟、音频时间戳短暂跳变、同步 H.264 显示。
- 单独 ALAC 不叠加发送端的 1.75 秒提前量：按实际包时长输入，验证内部起播和输入暂停后的调度队尾均小于 200 毫秒；模拟 40 毫秒输入抖动，检查原包顺序、时间戳连续性及双声道纯音。
- 暂停 1.1 秒后恢复，首包不能被旧音频游标改写；flush / reset 清空待播状态。
- 模拟解码器重建耗时 120 毫秒：单独 ALAC 在 flush 和同格式重配后重新锚定首包，不能继续使用已过期的播放截止时刻；音视频模式的音频 flush 不停止或倒退视频时钟。
- 每次检查再使用真实系统 decoder / output queue（静音）完成八次冷启动，注入 0 / 25 / 60 / 120 毫秒重建耗时，检查首包不晚到、有效包不丢失且 decoder 不失败。
- 起播和结束处的有效 ALAC 静音均保留；零 PCM 时长准确，与纯音相接的时间戳连续、解码频谱干净。
- 屏幕镜像仍使用原有低延迟策略；正常、缺省和异常大的时间戳提前量都不造成秒级等待。

这些时长断言检查播放器调度，不是扬声器端到端实测。80 毫秒缓冲也不保证掩盖 250 毫秒的真实网络停顿；不再用秒级延迟换取这个保证。
- 音量、静音、无效音量输入、停止、同分辨率重连。

## 窗口尺寸

`WindowBehaviorChecks.swift` 调用生产窗口控制器，但不显示窗口、不抢占焦点：

- 连接后的初始画布、手动调整大小、同方向的分辨率／比例变化，以及方形、无效尺寸。
- 横竖切换保留用户选定的尺度，并受显示器边界限制。
- 全屏内来回旋转不重置原窗口；退出全屏或进入全屏失败时，正确应用最终方向。
- 全屏内断开后恢复默认等待窗口，重连采用新的初始方向。

这些检查验证窗口控制器的尺寸和回调逻辑，不替代真实全屏 Space 动画的实机检查。

生成物位于 `.build/audio-tests/` 和 `.build/window-tests/`，不提交。纯音频谱检查不等同于真实音乐听感；这些检查也不能代替 iPhone / 抖音、Wi-Fi 抖动及真实输出设备上的实机复测。
